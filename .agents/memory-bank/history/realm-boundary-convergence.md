## Activity Log AL4 (2026-11-10)

The list consumes lightweight Realm summaries, sorted by descending start
time and ascending activity ID. It starts with 30 rows and expands the same
live query by 30 on each Load More. Inserts, updates and deletions reconcile
against the ordered prefix as a unit. Only that prefix resolves book titles
and builds values. Request bodies, headers, request steps and progress
history are read only by the detail query.

All three entrances share the list and retain their original scope. Numeric
book IDs are filtered within their library, including batch membership.
The task filter matches typed kinds. Failures Only matches typed Failed
rows and excludes cancellation, interruption and legacy records. Filter
changes replace the subscription and reset the window. Returning from a
detail keeps the window and stable row identities. Foreground and appearance
recalculate the same seven-day cutoff used by maintenance.

Detail reads and observes one stable activity ID with its own main-actor
view model. It can finish while the list is offscreen and shows an
unavailable message after deletion or expiry. Status, full saved request
diagnostics, headers and progress changes stay in the detail. Paused rows
have no finish time. Legacy timestamps are shown as last recorded, and
recovery timestamps are marked interrupted without inferring elapsed time.

The string write adapter and AppContainer forwarding are removed. Preview
and mock activities use typed writes. Realm schema 151 still reads the
historical type, result and request fields. AL3 ownership, retention,
background flush and download behavior remain in use.

The focused iPhone 17 suite passed 159 tests. The final full app test
target ran 1072 tests with one skip and zero failures, including 21 real
Calibre 9.11 contracts. All five standard UI journeys passed. The dedicated
Activity Log journey verified the three entrances, task and failure
filters, clearing, paging, and the expanded window on return. It passed
on iPhone 17, iPhone 7 / iOS 15.5, and iPad mini / iPadOS 26.5 at the largest
accessibility text size. The iPhone 7 run also passed 38 focused units.
An isolated iPhone 17 app against the real download proxy displayed a
running activity, then updated the same detail to succeeded with a finish
time while the list was hidden.

Legacy request and result preservation and interrupted recovery were verified
with file-backed migration fixtures and repository tests. Native interaction
with a historical row and Catalyst UI interaction were outside this run.
The final Catalyst build, Swift parse, project plist, Python syntax, Realm
boundary, legacy writer scan and diff checks passed. Logs and result bundles
are under `/tmp/YabrAL4`.

## Activity Log AL3 (2026-11-10)

Download activities use the attempt UUID and carry the library, book, format,
and sanitized request. The main actor publishes download state immediately and
chains only the logger submissions, so the logger accepts a start before any
transition for that attempt. Pause and resume keep the same UUID and record
increasing revisions with dates. Retry creates a new UUID. The delegate accepts
completion and progress only from the current running task and attempt. A
completion that arrives after pause, cancellation, or replacement at another
address cannot commit a staged file.

The download snapshot and the activity share the terminal failure message.
HTTP failures keep the status, including 401 and 403. Transport failures and
file failures use safe messages. The delegate checks the size, sets attributes
on the staged file, then moves or replaces it atomically before publishing
success. A save failure does not mark the format cached. The Book Detail
download-and-read route continues to use the current book and originating
workspace.

The logger has one writer and a bounded pending buffer. A flush waits for all
events accepted before its call, including the in-flight batch. Each barrier
reports failures only for batches it covers. Repository writes throw on
failure and run atomically on a serial queue. The logger retries twice after
the first failure, then reports and drops the failed batch. Subsequent batches
continue in order. Overflow drops new events and reports it to the system log.
Writes never change the business operation's outcome. Realm configuration
snapshots are locked during bootstrap and background reads.

Schema 151 adds optional process ownership, download format, and progress
history. Startup maintenance prunes with the same seven-day cutoff as the
list, then marks only previous-process typed running and paused rows
interrupted. Rows from schema 150 without an owner qualify. Current-process,
terminal and legacy rows keep their state. The repository's pruning watermark
blocks stale starts from resurrecting deleted history. Maintenance goes through
the same write ordering as ordinary events and never starts a download.

The aggregate app phase and the active scene set must both allow a background
flush. The app first drains accepted download submissions and uses a finite
UIKit background task for the logger. Expiration releases the lease. It may
cut short what gets written before suspension or termination. See
[SwiftUI scene phase](https://developer.apple.com/documentation/swiftui/scenephase)
and [UIKit background execution](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time).

AL4 can add paging, filters and independent live detail observation, and remove
the legacy write adapter and its preview wrapper. Keep legacy history readable,
the process ownership check, and the flush and retention contracts.

The immediate-cancellation test reproduced the legacy row and mismatched
UUID before AL3. A first focused run exposed a crash while copying a
published Realm configuration during reconfiguration. The final runs
passed after synchronizing configuration access.

The final iPhone 17 run passed 214 tests, including 21 real Calibre 9.11
contracts. iPhone 7 / iOS 15.5 passed 137 focused tests. The file-backed
schema 150 fixture preserves AL2 diagnostics, legacy text and a saved Folio
profile, and recovers an unowned typed operation. The earlier migration
fixtures still pass. The iOS Release and Catalyst builds and static checks
passed.

The opt-in AL3 UI test passed on a separate iPhone 17 Release installation
against the real server and loopback proxy. It covers HTTP 503, retry,
pause/resume, opening Folio after completion, cache clearing, cancellation
without opening, and the Cancelled activity. The native binary matched the
Release build. The older P3 and BD3 journeys reached Folio but stopped at
their existing introduction text check. Hardware and actual OS termination
were outside this run. Logs and result bundles are in `/tmp/YabrAL3`.

## Activity Log AL2 (2026-11-09)

`CalibreServerService.withActivity` gives each service operation an ActivityID.
The owner finishes the activity after validating and parsing the response,
including errors returned inside task values. The HTTP layer records each
request's status before mapping 401/403 to `authFailed`, and keeps the last
authentication challenge status when URLSession cancels. Request timings
use a monotonic clock. AL2 treats a parsed pending manifest as a successful
status retrieval and a rejected or malformed manifest as a failure.

Schema 150 adds optional per-request diagnostics to the main Realm.
A migrated 149 row still exposes its AL1 request and result, and legacy rows
still expose their original request and text. New snapshots remove URL
userinfo and fragments, redact query values outside the structural allowlist
and header values outside the safe list, and retain only JSON body structure
within a 4 KiB limit. Oversized and non-JSON bodies retain a byte count.
Diagnostic details avoid copying server response bodies. Legacy download
starts use the same request redaction and keep their existing write adapter.

## Activity Log AL1 (2026-11-09)

The logger accepts Sendable start and update values with the same
`ActivityID`, backed by the existing UUID string primary key. The first
start owns the ID. Updates for unknown IDs are discarded. Progress revisions
must increase from the initial revision of zero, so a replayed pause can't
undo a resume. The first terminal update wins from either running or paused
and sets the finish date. A terminal update carries optional HTTP status,
error category, and detail as separate values. The logger submits batches
in order even if a second flush arrives during an earlier write.

Schema 149 keeps legacy IDs, timestamps, type, result text, URL, method,
body, and headers. The migration marks those rows legacy and moves nonzero
`bookId` values to `bookIds`. A book query matches both its library ID and
membership in the list. The repository observes on the main actor and
returns snapshots with raw dates. Writes open their own Realm on the
repository's serial queue. The views format dates and show the legacy label
with the original result in Activity Details. The seven-day views still
observe only while visible. Book Detail's sheet retains its independent
reader-open dismissal subscription.

Current network and download callers write through the string adapter.
Its composite match is restricted to legacy rows. AL2 should submit typed
service completions at the parse and validation boundary. AL3 should reuse
each download UUID, order progress revisions, reject stale callbacks, and
handle background flush and interrupted attempts. AL4 can remove the
string write adapter and keep the legacy read mapping for saved logs.

Verification passed on iPhone 17 / iOS 26.5 with 175 focused tests and on
iPhone 7 / iOS 15.5 with 21 focused tests. Both include file-backed fixtures
with the actual 147/148 Activity Log table shape and a saved Folio profile,
plus repository updates, scopes, observation visibility, and reader-open
sheet dismissal. The larger run includes Book Detail, network service,
download, and server-scoped Realm tests. The final Catalyst build and
Swift parse, project plist, Realm boundary, and diff checks passed.
Logs and result bundles are under `/tmp/YabrAL1`. Verification covers
simulator tests and builds. The full suite, real Calibre, and native UI
interaction were outside this run.
